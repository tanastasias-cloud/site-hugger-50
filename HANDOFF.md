# GetGrow Academy — сайт getgrow.academy: краткая справка для Claude (1 страница)

Источник правды — репозиторий GitHub `tanastasias-cloud/site-hugger-50` (файлы `CLAUDE.md`, `PROJECT_NOTES.md`, `BRAND.md`).
Эта справка нужна, если доступа к репозиторию нет. Отвечай владелице **по-русски**, коротко и по шагам.

## Что это

Сайт коучинговой компании GetGrow Academy GmbH (Берлин): коучинг для частных лиц, компаний и клиентов Jobcenter (AVGS, §16k SGB II).
Основной язык сайта — немецкий. Страницы: главная, Privatpersonen, Unternehmen, AVGS, §16k, Coaches (+ страница каждого коуча),
Referenzen, Kontakt, Impressum, Datenschutz.

## Как устроен

- **TanStack Start (React) + Nitro**, пакетный менеджер **bun**. Хостинг — **свой сервер Hetzner** (Ubuntu): nginx → Node на
  `127.0.0.1:3000`, systemd-сервис `getgrow.service`, код в `/var/www/getgrow` (владелец — пользователь `getgrow`), HTTPS от Let's Encrypt.
- Supabase и Lovable Cloud **убраны**. Форма `/kontakt` пишет заявки в **SQLite** (`data/app.db`, вне git) и шлёт письмо на
  `info@getgrow.academy` через **Gmail API**. Секреты только в `.env` на сервере.
- Шрифты и цвета: Tenor Sans, DM Sans, Cormorant Garamond, Allura (у Allura нет кириллицы); основные цвета `#1a2e26`, `#3d6b55`, `#7fc4a0`.
- Страницы коучей берутся из `src/data/coaches.ts`; сейчас **11 карточек**. Страница ивента (15.11.2026) закрыта: `/event` — заглушка
  «Мероприятие окончено», старая страница в `archive/event-2026-11-15/`.

## Как выкладываются изменения (автодеплоя нет)

1. Claude правит код, собирает (`bun run build`), проверяет локально в браузере (десктоп **1440 px** и телефон **390 px**), коммитит
   (английское сообщение, один логический блок на коммит).
2. **Владелица сама делает `git push origin main`** (у Claude нет доступа к GitHub).
3. Для доступа к серверу Claude создаёт **одноразовый SSH-ключ**, а владелица добавляет его одной командой через свой ключ.
4. На сервере: `sudo -u getgrow git pull --ff-only origin main`, `sudo -u getgrow bun install`, `sudo -u getgrow bun run build`,
   `systemctl restart getgrow.service`; затем проверка живого сайта и логов.
5. **Временный ключ обязательно удаляется** после деплоя (остаётся только её постоянный ключ).

## Правила работы

- Делать **только то, что просили**; тексты и дизайн не менять, если речь о «цветах и размерах». Ничего не выдумывать:
  описания коучей — только из присланных материалов, то, что под NDA, не публиковать.
- Сначала проверка, потом слова «готово»: измерять в браузере, а не гадать.
- Пароли, токены, ключи **никогда** не вставлять в чат, файлы и коммиты; значения из `.env` не читать и не выводить.
- Не переписывать историю git (`force push` нельзя): репозиторий связан с Lovable, и его бот иногда возвращает файлы Supabase.
  В проекте есть скрипт `scripts/strip-lovable-supabase.sh`, он удаляет их и запускается при каждой сборке.
- Перед необратимыми действиями (удаление данных, правки конфигурации сервера) спрашивать.
